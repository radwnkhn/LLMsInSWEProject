## Behavior

`GET /comparisons?first_id=...&second_id=...` accepts two analysis IDs. Both must be owned by the current
user and refer to distinct, completed, measurable uploads of the same selected and analyzed lift. The
response includes `older`, `newer`, `metrics` and `fault_comparison`. Upload creation time determines the
order, even if a later analysis is a retry. Each video URL is signed only after both owners are checked.

The measurements table labels each minimum/maximum and its unit. Missing or blocked quantities display
as Not measured; numeric zero remains zero. The old top fault is checked against all newer rep values
using the existing fault catalog, camera requirements and saved not-measured checks. Confirmed evidence
can establish presence even with some missing reps; establishing absence requires values for every rep.

Earlier measurements-only fallbacks cannot supply a validated top coaching fault. Newer fallbacks can
still supply measurements for checking an earlier validated fault. Different camera angles are shown
with context rather than silently suggesting a direct improvement.

The comparison page is protected, cancels abandoned requests and provides Retry after load errors.
Browser tests build in `.next-e2e/` to avoid overwriting an existing development server's `.next/` files.
US-20 requires no database migration or new service credentials.

restarting that in-memory test mode clears its temporary accounts and uploads.
