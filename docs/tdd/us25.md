# US-25: Manage the fault list

Issue: [#27](https://github.com/radwnkhn/LLMsInSWEProject/issues/27).
Branch `beta/us-25-fault-list` starts from `origin/codex/us-19-us-20-us-21` (`af547c9`), because that
Beta branch was not yet merged into `main`. No branch for US-24 (adjust fault thresholds) existed, so
this story was designed to leave threshold editing to it (see [Room for US-24](#room-for-us-24)).

and `issues/create_github_issues/issues.py`. The tests were then written and committed on their own

no passes. The tests were also switched to `faults.X` attribute access so each test fails on its own
instead of the whole module failing to import.

All tests were AI-generated. None are marked manual; a team member should review and refine them as
required by `CLAUDE.md` and mark their own changes.

## Implementation

- **`backend/app/faults.py`.** `FAULTS` stays as the Alpha definitions and seeds everything else.
  - `Fault` gains `enabled` (default `True`).
  - `METRICS` lists, per lift, every measurement `measure_set()` computes, with the camera angles, joints,
    unit and frame label a fault built on it needs. A test keeps it in step with the measurement code and
    with `FAULTS`.
  - `new_fault()` builds a fault only from a `METRICS` entry. `edit_fault()` applies only
    `FAULT_EDITABLE_FIELDS` (name, short name, enabled).
  - `FaultCatalog` is a snapshot of the saved list: `faults_for()` returns enabled faults, and `get()`
    also returns disabled ones, for showing saved results.
  - The module functions `faults_for`, `fault_ids` and `get_fault` take an optional catalog and default
    to the Alpha list, so existing callers and tests behave the same.
- **Pipeline.** `process_analysis` reads `repo.list_faults()` once when an analysis starts and passes the
  catalog through the "not measured" checks, fault confirmation, key frames, prompt payload, JSON schema,
  validator, annotation and results.
  - The validator reports a cited disabled fault as `fault_disabled`. The correction loop sends that back
    to the LLM like any other validator error.
  - Comparisons use the saved list including disabled faults, so earlier results still compare.
- **Repository.** `list_faults`, `get_fault`, `create_fault` (raises `FaultExists`) and `update_fault`
  (only `FAULT_EDITABLE_FIELDS`), in memory and in Postgres.
  - Migration `20261111000000_us25_fault_list.sql` creates `public.faults` with every `Fault` field,
    enables RLS with an admin-read policy, and seeds the 13 Alpha faults. The seed was generated from
    `FAULTS`.
- **API.** All three endpoints use the existing `admin_user` dependency, so they return 401 when signed
  out and 403 for non-admins.
  - `GET /admin/faults` returns faults and selectable measurements per lift.
  - `PATCH /admin/faults/{lift}/{id}` accepts `name`, `short_name` and `enabled` only; other fields get
    422, unknown faults 404.
  - `POST /admin/faults` returns 201. Bad input gets 422, a duplicate ID 409.
- **Frontend.** `/admin/faults` (`AdminFaultList`) shows one table per lift with Edit and Disable/Enable,
  plus an "Add a fault" form whose measurement is a select limited to that lift's measurements. The
  Analyses admin page links to it. `ErrorSummary` labels the new `fault_disabled` validator error.
- **Test mode only.** Sign-ups at `@admin.test` become admins (`TEST_ADMIN_DOMAIN`), so browser tests
  can reach admin pages. Production auth (Supabase `app_metadata.role`) is unchanged.

## Room for US-24

US-24 can add threshold editing without a rewrite:

1. Add `"threshold"` to `FAULT_EDITABLE_FIELDS` and a numeric check in `edit_fault()`.
2. Add `threshold` to `FaultEditBody` and to the edit form.
3. Add its change log (who, when, old and new value) inside `update_fault`.

The `public.faults` table already stores the threshold, the repository already routes every edit
through that one set, and analyses already read thresholds from the saved catalog.

## Assumptions

- **"Short description"** is the existing `short_name` field (for example "knee cave"), which validator
  messages already use. No new description field was added, because that would change the LLM prompt and
  so Alpha behavior.
- **New faults** are built only on a measurement the lift already computes, picked from a list. Camera
  angles, joints, unit and frame label come from that measurement. The admin also sets a starting
  threshold and direction, because a fault can't be confirmed without one; changing thresholds afterwards
  is US-24. The admin also chooses the fault ID (3-40 lowercase letters, digits or underscores) and the
  category.
- **No deletes.** Faults are only disabled, because saved analyses refer to them by ID. Earlier results
  and comparisons still show a fault that was disabled later.
- **Disabled faults** are also dropped from the schema's allowed IDs, the confirmed faults and the
  "not measured" checks for new analyses. They stay in the comparison measurement table.
- **Snapshot per analysis.** Each analysis uses the fault list as it was when it started. An admin change
  made while an analysis runs applies from the next analysis on.
- **New faults are listed after the lift's existing faults.** In the prompt, safety faults still come first.
- **The mocked LLM** (`RuleFollowingLLM`) now follows the fault list in its request, as a real model
  would, and uses a generic cue for faults an admin added.
- **Test-mode admins** use the reserved `.test` domain (`admin.test`). This only exists with
  `ALIBI_TEST_MODE=1`.
