## Cleanup and coordination

Both DELETE endpoints require a JSON body with `confirmed: true` as a strict boolean. Missing,
false, string or numeric values fail with 422. `DELETE /uploads/{upload_id}` checks the owner's
session even for admins; unknown/inaccessible uploads return 404. `DELETE /account` always targets
the authenticated account, not a user ID supplied by the client.

Storage deletion happens before database cleanup. A failed Storage API operation leaves database
records available for retry. Account deletion removes all files beneath the user's video and frame
prefixes, including orphaned objects, then removes their database records and Auth account. An Auth
failure is reported as incomplete deletion and can be retried; some requested cleanup may already
have occurred. No success response is sent until the cleanup steps complete. Production removal uses
the existing server-only service role key; the key is never sent to the browser.

Queued/processing analyses return 409 with a wait-and-retry message. Upload creation, retries and
deletion share a per-user guard so new work cannot race past account cleanup. In-memory tests use
reentrant locks. Postgres uses advisory locks and pins the owner's pooled connection for queries
inside the guard, including nested operations. Authentication rechecks a missing profile under the
same guard before recreating it, so an in-flight request cannot resurrect a deleted account.

An upload's candidate frame paths include every analysis attempt, even if a frame was stored just
before an attempt failed. Existing foreign-key cascades remove the related measurements, attempts,
validator results and ratings. US-21 requires no schema migration.

The implementation follows Supabase's [Storage deletion guidance](https://supabase.com/docs/guides/storage/management/delete-objects)
and [Auth admin deletion contract](https://supabase.com/docs/reference/javascript/auth-admin-deleteuser).
Production adapters are verified with mocked HTTP requests; no Supabase project is contacted.

## Run

With the project's virtual environment active:

```bash
cd backend
python -m pytest tests/test_us21_deletion.py tests/test_us21_adapters.py tests/test_setup02_repository.py -k us21 -q
python -m pytest --cov=app --cov-report=term --cov-report=xml
```

```bash
cd frontend
npm test -- us21
npm run test:coverage
npm run lint -- --ignore-pattern coverage/**
npx tsc --noEmit
npm run e2e
```

`E2E_BUILD_DIR=.next-us21-e2e` to preserve the existing US-20 demo on ports 8765/3123.
