## Tests first

The acceptance criteria were agreed first and committed in `docs/User_Stories_and_Acceptance_Criteria.md`
and `issues/create_github_issues/issues.py`. The tests were then written and committed on their own
(`Add failing US-26 AI usage and cost tests (red)`) before any production change, and run against the
existing app. Provider replies are mocked with `httpx.MockTransport` using realistic Claude, OpenAI and
Gemini response bodies, including their usage fields. No real LLM API is called.

### Tests changed or added during the green phase

- **`test_us26_summary_unit_totals_average_and_retry_share`** expected 3M input tokens. Token totals
  rightly include the attempt whose model has no price (4M); only its dollars are left out.
- **`test_us26_cost_summary_counts_only_analyses_in_the_date_range`** moved the wrong upload out of the
  range. The shared mocked LLM fails only its first reply, so only the first upload has a retry.
- **The browser cost test** expected a retry share of at least 1%. When the full suite runs, the
  summary also covers every other browser test's analyses, so the share is about 0.4%.
  - This revealed that the page rounded a real 0.4% share to "0%".
  - New test first, confirmed failing: `us26_a_small_but_real_retry_share_is_not_shown_as_zero`.
  - The page now shows "<1%", and the browser test accepts it.
- **`formatCost`** showed a real $0.000035 attempt as "$0.0000". A failing case was added first; it now
  shows "<$0.0001".
- **`test_us26_default_price_file_covers_each_providers_default_model`** now also checks that the price
  file is inside `backend/app/`. Reviewing `backend/Dockerfile` showed it copies only `app/` and
  `scripts/`, so a price file at `backend/llm_prices.json` would have been missing from the deployed
  image and stopped the API from starting. The file was moved to `backend/app/llm_prices.json`.

## Implementation

- **Usage from each provider (`backend/app/llm/providers.py`).** `LLMReply` gains `provider` and `model`.
  - Claude reads `usage.input_tokens` / `output_tokens` and the response's `model`.
  - OpenAI reads `usage.prompt_tokens` / `completion_tokens` (which include reasoning tokens) and
    `model`.
  - Gemini reads `usageMetadata.promptTokenCount` and adds `candidatesTokenCount` and
    `thoughtsTokenCount` for output. Gemini bills thinking tokens as output, but the old code dropped
    them. Its model comes from `modelVersion`.
  - A missing or null counter counts as 0. A missing model falls back to the configured one.
- **Every attempt is recorded.** `AttemptLog` gains provider and model. A request that fails before any
  reply records the client's provider and model with zero tokens. `process_analysis` saves both with
  each attempt.
  - Migration `20261112000000_us26_llm_usage.sql` adds nullable `provider` and `model` to
    `llm_attempts`, and an index on `analyses.created_at`.
- **Prices (`backend/app/pricing.py`, `backend/app/llm_prices.json`).** Prices are dollars per million
  input and output tokens, per model. The default file ships with the backend; `LLM_PRICES_FILE` points
  at another.
  - A dated snapshot name (`gpt-4.1-mini-2025-04-14`) uses its base model's price.
  - An unknown model's cost is `None`. A malformed file stops start-up with an error that names it.
  - Test mode and tests add a `mock-coach` price for the mocked LLM; it is never in the shipped table.
- **API.** Both endpoints use `admin_user`, so they return 401 when signed out and 403 for non-admins.
  - `GET /admin/analyses/{id}` adds `provider`, `model` and `cost` to each attempt, plus a `usage` total.
    The total is unknown if any attempt's model has no price.
  - `GET /admin/costs?start=YYYY-MM-DD&end=YYYY-MM-DD` returns analyses, attempts, retries, tokens,
    total cost, average per analysis, retry cost and share, and the count of unknown-cost attempts.
- **Frontend.**
  - The analysis detail page shows "provider · model · tokens · cost" on each attempt, and an "AI usage"
    total.
  - The admin page has an "AI cost" section with From and To dates.
  - `formatCost` shows four decimals below $1, "<$0.0001" for tiny real costs, and "Unknown cost" for
    `null`.

## Assumptions

- **Price values and their source.** Every entry needs checking against current provider pricing before
  anyone relies on the totals. `llm_prices.json` records its source and check date.
  - **Claude** (`claude-opus-5-5` $4 / $20, `claude-sonnet-5-5` $2 / $10, `claude-haiku-5-5` $0.10 /
    $0.50 per million tokens) is from Anthropic's model and pricing table as cached on 2026-11-03.
  - **`gpt-4.1-mini`** ($0.40 / $1.60) and **`gemini-2.5-flash`** ($0.30 / $2.50) are their 2025 list
    prices, not re-checked for this story.
  - The prices are standard-tier list prices: no prompt caching, batch or volume discounts, and no
    long-context tiers.
- **Costs are computed when shown,** at the prices in the table now. They aren't stored per attempt.
  Adding a missing model's price fixes its old "Unknown cost" attempts, but a later price change also
  changes old estimates.
- **Unknown costs are counted, not guessed.** In summaries they are left out of the dollar totals and
  shown as a count. On an analysis, one unpriced attempt makes the total unknown, so it is never
  understated.
- **Retries.** Correction retries are attempts 2 and 3. The retry share is their cost divided by the
  total cost.
- **The date range** uses inclusive UTC dates and filters by when each analysis was created. It defaults
  to the last 30 days ending today. "Analyses" means analyses with at least one LLM attempt.
- **Failed requests** record the configured provider and model with zero tokens, so they cost $0.00.
- **Out of scope.** The old placeholder criterion "warn at 80% of a monthly budget" wasn't in the agreed
  criteria, so it was left out. It could be a follow-up story.
