## Acceptance coverage

| Acceptance criterion | Tests |
| --- | --- |
| Uploading → Measuring → Writing feedback → Checking without refresh | `test_us19_processing.py`: saved stages and stage observed inside pose estimation, LLM generation and validation; `us19-processing.test.tsx`: upload progress, active steps and sequential polling; `us19-processing.spec.ts`: browser polling and no document reload |
| Results open automatically | Backend terminal results; frontend automatically replaces progress with results and stops polling; browser automatically displays the completed result |
| Failure shows an error and Retry | Backend terminal failure, saved-video retry, failed-attempt preservation, rejected retries of active/completed jobs and ownership; frontend worker/network failure, retry failure and disabled duplicate submit; browser real worker failure followed by a successful retry with just one upload |

The browser progress test holds API snapshots at each stage because the synthetic pipeline finishes
between polls. Backend tests independently verify the stages around the actual processing calls.
Browser tests run with mocked pose data and LLMs; no live LLM or Supabase service is called.
The retry browser test uses a test-mode `fail_once-...` filename to trigger a transient pose failure,
then calls the real retry API and waits for the new result. A threaded backend test also pauses each
processing step and reads it through the real API while the worker is running. A frontend test verifies
that a stalled status request times out and presents Retry.

## Implementation

`processing_stage` is a nullable field on analyses, added by a new migration. The job's existing
queued/processing/done/failed states stay compatible with history and admin consumers. Each real
generation/validation attempt saves its stage; completion and failure clear it.

`POST /analyses/{id}/retry` returns 202 and a new analysis ID for an owner-accessible failed analysis.
It uses the original upload and preserves its failed analysis, avoiding duplicate measurement and
attempt-number constraints after a partial failure. Non-failed analyses return 409, inaccessible or
missing IDs return 404, and unauthenticated requests return 401.

The frontend polls sequentially, cancels pending reads on navigation, ignores stale responses, stops
on terminal states, and offers a reconnect action after read errors. Reads time out after 30 seconds.
